## 구현 범위

일반 게임에서 저장된 소유 장비를 확인하고, 주/보조 무기 두 슬롯에 장착하며,
아이템별 옵션이 실제 사격·장전·약점 피해에 적용되게 한다. 기존 소모품 인벤토리는 유지한다.
드롭·상점 거래·분해·제작·랜덤 옵션 추첨·새 적/무기는 이번 범위가 아니다.

### 1. 프로필 연결과 최초 장비

- 신규 `rpg/session.py` 등에 프로필 로드, 장착 변경, 저장의 연결 로직을 둔다.
- `game.py`가 새 저장소를 로드한다. 테스트용 저장 경로 또는 SaveStore 주입을 지원한다.
  ShowBase 생성자에 RPG 전용 kwargs를 넘기지 않는다.
- source=new인 새 프로필에는 일반 등급 기본 무기 4종을 한 번 지급하고 PISTOL/SHOTGUN을
  주/보조 슬롯에 장착한다. 옵션 없는 기본품이며 기존 수치를 그대로 사용한다.
  신규 지급은 이 단계의 명시적인 게임 정책이다. 1단계 new_profile() 자체는 빈 상태를 유지한다.
- `unlocks`의 `starter_loadout_v1` 표시로 재지급을 막는다. 같은 정책이 필요한 기존 빈 프로필도
  이 표시가 없고 items가 비어 있을 때만 지급한다. 물건이 있는 프로필에 중복 지급하지 않는다.
- 성공한 장착/해제/잠금 변경을 저장한다. 입력 후보를 복제·검증·저장한 뒤 런타임에 반영한다.
  저장 실패 시 기존 장비와 옵션을 유지하고 사용자에게 짧은 오류를 보여준다.
- 손상/미지원 버전/읽기 권한 오류를 빈 새 프로필로 덮지 않는다. 원본을 보존하고
  일반 RPG 플레이 시작을 막으며 이유를 표시한다. 테스트 모드는 별도로 이용 가능하게 한다.
  정상 백업 복구는 warnings를 표시한다. 프레임마다 저장하거나 종료 시 무조건 덮어쓰지 않는다.
- 새 게임·스테이지 이동·사망으로 영구 장비를 지우거나 기본품을 재지급하지 않는다.
  이번 단계에서 미확보 전리품이나 사망 손실 정책은 추가하지 않는다.

### 2. 장비 UI

- 기존 인벤토리에 `소모품 / 장비` 탭을 추가한다. 소모품 사용·퀵슬롯·키보드 닫기를 보존한다.
- 장비 패널은 가급적 신규 `rpg/equipment_ui.py`로 분리하여 ui_manager.py 증대를 줄인다.
- 소유 아이템 목록은 스크롤 가능. 이름, 등급, 레벨, 장착 상태를 표시한다.
- 선택 상세: 확정된 옵션, 실제 기본 피해/약점 배율/장전 시간, 비교할 슬롯의 장비 대비 변화량.
  장전 시간은 낮아지면 좋은 값으로 표시한다. 내부 UID나 저장 파일 경로를 일반 UI에 노출하지 않는다.
- `주 무기 장착`, `보조 무기 장착`, `장착 해제`, `잠금/해제` 제공.
  잠금은 추후 분해 보호 표시이며 장착 자체를 막지 않는다. 재료는 표시만 하고 장착 불가.
- 슬롯을 선택해 비교 대상을 명확히 한다. 마지막 무기까지 해제해 일반 플레이가
  무장 해제 상태가 되지 않도록 마지막 하나 해제를 막는다.
- 같은 UID는 양 슬롯에 장착 불가. 서로 다른 UID의 같은 총기 종류는 동시 장착 가능.
- 실제 창 1600×900에서 텍스트 잘림·버튼 겹침·스크롤·ESC/Tab 닫기를 검사한다.
  오프스크린 캡처와 입력 콜백 검증을 작성해도 된다. 유저의 마우스를 지속적으로 가로채지 않는다.

### 3. 무기 전환·옵션 연결

`resolve_weapon_config(WEAPON_CONFIGS, catalog, item)`을 사용한다.
이 모듈은 순수 계산이며 사격 때마다 매번 호출하지 않는다. 장착/아이템 변경 시 계산해 캐시한다.

- damage_mult → 기본 damage, reload_time_mult → reload_time,
  weakpoint_mult → headshot_mult. 기존 퍽·불릿타임·콤보는 이후 기존 경로에서 적용한다.
- 등급/레벨 자체로 숨은 수치 보너스를 추가하지 않는다.
- 전역 WEAPON_CONFIGS 또는 다른 인스턴스의 수치를 수정하지 않는다.
- 일반 게임은 두 슬롯으로만 전환한다. 1/2는 주/보조 슬롯, 휠과 다음/이전은 채워진 슬롯만 순환.
  기존 직접 3/4 선택 바인딩으로 미장착 무기에 접근하지 못하게 한다.
- current_weapon은 모델·사운드용 무기 종류 키로 유지하고 active_item_uid/active_slot을 별도로 둔다.
  같은 종류 두 아이템으로 전환해도 UID가 다르면 실제 옵션과 상태가 바뀌어야 한다.
- 같은 종류 아이템의 탄창/슬라이드 잠금은 UID별로 관리한다. 예비탄은 기존 종류별 풀을
  공유하여 슬롯 교체로 복제되지 않게 한다. 인벤토리에서 다시 장착해도 탄창이 무료 충전되면 안 된다.
  새 런의 정상 탄약 초기화와 스테이지의 keep_ammo 동작은 보존한다.
- 장전/ADS 도중 슬롯 변경은 기존 전환 정리 로직을 재사용한다. 장전 취소 시 탄약 복제 금지.
- 사격 레이캐스트, 샷건의 각 산탄, 도탄의 기본 피해, 장전 타이밍/사운드/애니메이션에서
  effective config를 일관되게 사용한다. 고정 피해 원소 퍽을 임의로 무기 옵션 배율에 포함하지 않는다.
- HUD는 현재 아이템의 이름/등급과 탄약을 보여준다.
- 기존 테스트 모드/사격장은 프로필을 수정하지 않고 기존 4종 무기를 자유롭게 시험할 수 있어야 한다.
  RPG 연결이 없는 기존 CombatSystem 테스트/도구는 원래 동작으로 fallback한다.

## 확인된 기존 연결 지점

- `game.py`: open_inventory/close_inventory, start_game/restart_game, start_test_mode,
  `_on_inventory_use_item`, `combat.reset_state(... keep_ammo=...)` 호출 지점.
- `player_controller.py`: setup_input의 무기 선택/전환 바인딩과 소모품 inventory.
- `ui_manager.py`: _setup_inventory_ui, show_inventory, hide_inventory, _refresh_inventory_ui,
  update_ammo. 기존 소모품 데이터는 영구 장비 items와 다른 구조다.
- `combat_system.py`: switch_weapon은 같은 종류면 조기 반환하며 weapon_states가 종류별이다.
  두 개의 같은 종류 아이템 지원 시 이 부분을 반드시 검토한다.
  next_weapon/prev_weapon은 현재 WEAPON_ORDER 전체를 순회한다.
  shoot/reload/update/reset_state와 WEAPON_CONFIGS 직접 참조를 함께 확인한다.

## 필수 검증

- 임시 디렉터리에서 최초 시작 → 기본품 4개 → 재시작 후 재지급 없음.
- 장착/해제/잠금 저장 후 재실행 복원. 소모품 리셋이 영구 장비를 지우지 않음.
- 같은 AR 종류의 두 UID에 다른 옵션을 주고 전환했을 때 피해가 분리됨.
- 실제 CombatSystem 경로로 일반 명중·약점 명중·장전 시간을 확인. 계산 함수만 검사하면 부족함.
- 퍽과 옵션이 한 번씩 적용되며 반복 전환/새 런에서 배율이 누적되지 않음.
- 두 슬롯 전환, 빈 슬롯, 마지막 무기 해제 거부, 재료 장착 거부, 동일 UID 중복 거부.
- 전환/재장착/장전 취소로 탄약이 늘지 않음. keep_ammo 보존.
- 저장 실패 시 UI/프로필/전투 상태가 서로 일치하며 기존 상태 유지.
- 손상/미지원 세이브는 덮지 않음. 테스트 모드는 실제 저장에 영향을 주지 않음.
- 모든 자동 검사·프리뷰는 임시 저장소를 주입한다. 기존 통합 스크립트가 기본 경로를
  사용한다면 검증 실행 전에 안전하게 임시 경로를 주입하는 방식으로 실행한다.
- `.venv/Scripts/python.exe -m unittest discover -s tests` 및 새 통합 검증 실행.

RESULT.md에 변경 파일, 사용법, 실제 테스트 결과, UI 캡처, 남은 문제를 간결하게 기록한다.
