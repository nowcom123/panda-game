# 작업 2: 관문 증원 흐름 개선

## 목표와 작업 방식

안티그래비티가 구현·테스트·결과 보고까지 담당한다. 코덱스 사용량을 줄이기 위해 별도 계획 승인 없이 이 문서의 범위에서 진행하고, 최종 보고는 간결하게 작성한다.

플레이 경험 목표: 관문에 접근하면 증원을 예고하고, 제한된 무리가 나타나며, 처치 후 재정비 시간을 얻는다. 적을 죽였다는 이유로 즉시 새 적이 채워지지 않아야 한다. 아래 수치는 첫 플레이테스트용 가설이며 재미나 난이도가 검증된 값이라고 표현하지 않는다.

## 기존 코드와 변경 범위

현재 MonsterDirector에는 45m 진입 2마리, 25m 진입 3마리, 32m 내 4초 주기 증원, 관문 근처 처치 시 65% 재증원이 있다. EscapePortalManager에는 사수 중 2초 주기 증원이 있다. 이 5개 경로를 단일 웨이브 제어로 대체한다.

작업 전 적용되는 AGENTS.md 및 git status/diff를 확인한다. 작업 1의 판정·설정 수정, 사용자의 무기·반동·UI 수정과 그 이후 변경을 보존한다. 전체 파일 교체나 git reset/restore, 자동 커밋·푸시는 하지 않는다.

허용 범위: 관문 증원 제어, 증원 위치 선정, 최소 HUD 안내, 해당 생명주기 및 테스트. 신규 적/무기/맵/보상/그래픽 리소스는 추가하지 않는다. 초기 수호 몬스터·순찰대, 보스 체력·패턴·38m 출현 조건, 기존 이동속도 배율은 유지한다.

## 1. 단일 웨이브 제어

MonsterDirector 내부 또는 작은 별도 모듈에 상태를 한곳으로 모은다. 게임·포털·디렉터에 별도 증원 타이머를 중복 유지하지 않는다.

초기 파라미터를 이름 있는 상수 또는 작은 설정 객체로 모은다:

| 항목 | 초기값 |
|---|---|
| 관문 증원 작동 반경 | 플레이어-관문 45m 이하 |
| 스테이지당 최대 웨이브 | 3회 |
| 웨이브당 총 출현 목표 | `2 + min(max(stage - 1, 0), 2)`마리 |
| 출현 전 경고 | 2.0초 |
| 동일 웨이브 출현 간격 | 0.75초 이상 |
| 웨이브 종료 후 재정비 | 8.0초 |
| 다음 경고를 허용하는 주변 생존 적 수 | 관문 45m 내 6마리 이하 |
| 증원 시 전체 생존 적 상한 | 16마리, 보스 포함 |
| 출현 단계 최대 지속시간 | 6.0초 |

상태 예시: WAITING → WARNING → SPAWNING → REST → WAITING, 3회 소진 시 EXHAUSTED.

- WAITING: 범위 안이고 주변 생존 적이 6마리 이하일 때 경고를 시작한다. 초기 수호군이 많으면 먼저 싸우게 되는 것은 의도된 동작이다.
- WARNING: 2초 동안 실제 출현하지 않는다. 완료 후 첫 적을 출현시킬 수 있다.
- SPAWNING: 0.75초 이상 간격으로 한 마리씩 출현을 시도한다. 한 프레임에 여러 마리를 생성하지 않는다. 매 시도 직전에 위치와 생존 적 상한을 재검사한다.
- 목표 수를 채우거나 출현 단계 6초가 지나면 해당 웨이브를 종료한다. 실패한 수량은 버리고 다음 웨이브로 이월하지 않는다. 0마리 생성이어도 경고를 거쳐 시작한 웨이브 1회를 소비한다.
- REST: 8초 동안 신규 증원 없음. 기존 적은 정상 행동한다. 그 뒤 WAITING의 주변 적 수 조건을 다시 확인한다.
- 3회 이후 해당 스테이지에서는 일반 관문 증원 종료. 처치·방어 재진입으로 횟수를 복구하지 않는다. 초기 적과 보스는 이 예산에 포함하지 않는다.
- 사망/시체는 인원수에서 제외한다. 상한은 신규 증원 허용 여부에만 적용하며, 초기 적이 16마리를 넘더라도 기존 적을 삭제하지 않는다.

### 이탈·정지·보스 정책

- 반경 밖에서는 출현과 모든 웨이브 시간 진행을 멈춘다. 재진입 시 WARNING은 온전한 2초를 다시 제공한다. SPAWNING 도중 이탈한 경우에도 재진입 시 같은 웨이브의 남은 수량 앞에 2초 경고를 다시 제공한다. 이때 웨이브 횟수나 6초 출현 시도 예산을 새로 지급하지 않는다. REST 잔여시간도 보존한다.
- SHOP/INVENTORY/PAUSED/AAR/INTRO/GAME_OVER/VICTORY 및 테스트 모드에서 진행·출현하지 않는다.
- 일반 플레이의 raw_dt로 웨이브를 진행한다. 불릿타임 world_dt를 사용해 임의로 타이밍이 늘어나지 않게 한다. 실제 메인 루프에서 프레임당 1회만 호출한다.
- 살아 있는 보스가 있으면 새 일반 증원은 중지한다. 현재 진행 중 웨이브가 있다면 잔여 출현을 취소하고 그 웨이브 1회를 소비한다. 아직 WARNING에 들어가지 않은 WAITING은 소비하지 않는다.
- 보스 생존 중 REST 시간을 소비하지 않는다. 보스 사망 후 남은 웨이브가 있으면 최소 8초 재정비 뒤 다음 경고를 시작한다. 보스 처치 보상·불릿타임·필수 격파 조건은 보존한다.
- 재시작/다음 스테이지/타이틀/테스트 모드 전환에서 상태와 안내를 정리한다. 새 일반 스테이지는 3회 예산으로 시작한다.

## 2. 출현 위치의 안전 조건

spawner.spawn_reinforcement_monster 및 관문 후보 선정을 정리한다. 실제 증원 생성에 사용되는 모든 경로가 다음 조건을 거치게 한다:

- 관문에서 10~30m, 플레이어에서 최소 12m 이상.
- 로드된 청크 안이며 맵 경계, 기둥, 벽, 관문 충돌체와 겹치지 않는다. 정예 배율을 포함한 생성할 종의 실제 몸체 반경을 고려한다. 검사를 위해 무거운 모델을 반복 생성하지 않는다.
- 같은 웨이브에서 이미 선택한 위치 및 기존 생존 적과 몸체가 겹치지 않는다.
- 플레이어가 보는 방향에서 갑자기 나타나지 않도록, 수평 시야각 안이고 벽에 가리지 않은 위치를 제외한다. 현재 렌즈 FOV와 카메라 방향을 사용한다. 시야각 밖이거나 벽 뒤인 위치는 허용한다. 모든 후보가 막히면 출현을 건너뛴다.
- 시야 차단 검사는 플레이어-후보 사이 전체 선분의 충돌체를 사용한다. 후보 근처 충돌체만으로 벽 뒤라고 판단하지 않는다. 미로드 구역을 통과하는 선분은 보수적으로 제외해도 된다.
- 스폰 직전에 다시 검사한다. 경고 중 플레이어가 이동하거나 방향을 바꿀 수 있다.
- 안전 후보가 없을 때 플레이어 근처/임의 좌표로 강제 출현하는 기존 fallback은 제거한다. None 반환을 정상 실패로 처리한다.
- 매 틱 전체 맵을 스캔하지 않는다. 관문 확정 시 후보 좌표를 캐시하고 새 맵/새 관문에서 무효화한다. 실시간 안전 조건은 출현 시도 때 검사한다.
- 기존 적 종류 가중치, 체력 배율, 정예 확률은 유지한다.

## 3. 탈출과 HUD

- 5초 사수, 반경 3.8m, 이탈 시 사수 진행 리셋, 3스테이지 이상 보스 필수 격파는 유지한다.
- 사수 도중 별도의 2초 주기 증원을 없앤다. 웨이브 완료를 탈출의 새 필수 조건으로 만들지 않는다. 재정비 구간에 5초 사수로 탈출할 수 있는 것은 의도된 보상이다.
- 오래된 game.gate_reinforce_timer, door_defense_spawn_timer, property 등은 참조를 확인하고 불필요하면 정리한다. 같은 이름으로 새 의미를 몰래 부여하지 않는다.
- 기존 HUD 스타일로 작은 관문 증원 상태를 표시한다. 예: `증원 경고 1/3 · 2.0초`, `증원 접근 1/3`, `재정비 · 8.0초`, `추가 증원 종료`.
- 경고 진입 시 기존 경보음을 1회 재사용한다. 매 프레임 재생하지 않는다. 보스 봉쇄 안내와 사수 진행률을 덮어쓰지 않도록 증원 상태는 별도 작은 라벨로 표시한다.
- 게임 내부 변수명, 실패 사유, 디버그 수치 등 구현 세부는 플레이 UI에 노출하지 않는다. 반경 밖/정지 메뉴/테스트/종료에서는 상황에 맞게 숨기고 복귀 시 정상 복원한다.

## 4. 테스트 및 확인

기준은 작업 1 종료 시 104개 테스트 통과다. 현재 작업 시작 시 실제 테스트 수도 확인한다.

중요: 작업 1의 `2초마다 방어 증원` 테스트는 이번에 의도적으로 바뀌는 규칙이다. 구식 요구를 유지하기 위해 사용하지 않는 타이머를 남기지 않는다. 해당 테스트를 `사수 자체는 별도 증원하지 않음`과 새 웨이브 생명주기 검증으로 대체하고 이유를 보고한다. 다른 기존 테스트는 약화하거나 skip하지 않는다.

필수 동작 검증:
1. 2초 경고 전 출현 0회, 경고 후 간격 준수, 큰 dt에서도 한 프레임 다중 생성 없음.
2. REST 8초 동안 출현 없음, 처치 직후 보충 없음, 세 웨이브 이후 추가 출현 없음.
3. 주변 적이 6마리보다 많으면 다음 경고 보류, 상한 16에서 출현 없음. 시체는 제외.
4. 안전 후보 없음/부분 성공/상한 도달 시 최대 6초 후 종료, 무한 재시도와 다음 웨이브 물량 누적 없음.
5. WARNING/SPAWNING/REST 각각 이탈·재진입 시 시간과 횟수 정책 준수.
6. 실제 메인 루프 연동에서 1회 갱신, 메뉴·테스트 모드 정지, 불릿타임과 무관한 raw_dt 사용.
7. 보스 출현 시 일반 증원 중지, 격파 후 최소 8초 재정비, 기존 보스 출현/탈출 봉쇄 동작 유지.
8. 실제 restart_game 및 advance_to_next_stage 진입점을 호출해 예산·타이머·캐시 초기화 확인. 무거운 렌더링/생성만 mock 처리한다.
9. 거리 12m 경계, 벽/관문 충돌, 미로드 청크, 플레이어 정면의 열린 시야, 벽 뒤, 뒤쪽 후보, 정예 반경 및 기존 적 중첩을 검증한다. 실제 안전 판정 함수를 실행하며 전체 검사를 항상 True로 mock하지 않는다.
10. 기존 사수 5초 성공/이탈 리셋 유지, 사수 진입으로 웨이브가 중복 시작하지 않음.

명령:
`.\.venv\Scripts\python.exe -m unittest discover -s tests -q`
`git diff --check`

가능하면 일반 1스테이지와 보스 스테이지의 짧은 수동 플레이도 확인한다. 실제 GUI 플레이 여부를 명시하고 자동 테스트만으로 재미·공정성이 입증되었다고 주장하지 않는다. 별도 대규모 벤치마크나 새 패키지는 필요 없다. rankings.json을 테스트로 변경하지 않는다.
