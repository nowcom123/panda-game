# 작업 2 검토: 완료 전 보완

코덱스 확인: 전체 119개 테스트 통과, git diff --check 공백 오류 없음. 다음 문제 때문에 아직 완료 판정하지 않는다. 구현·검증·REPORT.md 갱신은 안티그래비티가 수행한다. 기존 사용자 작업은 보존한다.

## 1. 생성 전 반경과 실제 몬스터 반경 불일치

spawner.spawn_reinforcement_monster는 `getattr(cls, 'col_radius', 0.40)`을 사용하지만 monster.py의 반경은 클래스 속성이 아니라 `self.col_radius`다. 따라서 모든 종을 0.40으로 검사한다. 오크는 실제 0.45, 정예는 0.5625인데 검사값은 0.50이 되어 벽 겹침을 놓칠 수 있다.

- 생성 전/후에 공유하는 종별 기본 반경 정의를 만들고 정예 배율을 일관되게 사용한다. 검사 목적으로 모델을 반복 생성하지 않는다.
- 실제 spawn_reinforcement_monster 경로에서 오크/정예 오크를 선택하도록 난수를 고정하고, 검사 반경이 실제 생성 반경과 일치하는지 검증한다.
- 벽까지 거리 0.53m인 후보는 정예 오크에 대해 거절되는지 검증한다. 안전 함수에 임의 반경 0.60을 직접 넣는 테스트만으로 대체하지 않는다.

## 2. 빈 청크 목록에서 안전 검사 우회

is_spawn_position_safe의 `chunks is not None and len(chunks) > 0` 조건은 None/빈 dict이면 로드 여부 및 벽 검사 자체를 건너뛴다. 뒤쪽 후보라면 청크가 전혀 없어도 허용될 수 있다.

- 청크가 없거나 후보 청크가 없으면 반드시 False를 반환한다. 실제 collision.get_nearby_colliders를 사용한다.
- 생산 코드의 `game.test_colliders` 전용 경로를 제거하고 테스트에서 실제 청크 자료구조(cell_colliders)와 커스텀 충돌체를 구성한다.
- 빈 dict, None, 다른 청크만 로드, 정상 청크, 후보/시야 선분의 충돌 검사 각각을 검증한다. 공용 커스텀 충돌체는 테스트 후 정리한다.

## 3. HUD 숨김·생명주기 처리가 실제 게임 경로에 연결되지 않음

GateWaveManager.update에서 메뉴일 때 숨기는 코드는 있지만 실제 game.update는 메뉴/종료 상태에서 디렉터 호출 전에 반환한다. 테스트 모드도 MonsterDirector의 일반 웨이브 처리 전 반환한다. gate_wave_status_text는 별도 OnscreenText여서 전환 시 이전 안내가 남을 수 있다. reset 호출은 현재 재시작/다음 스테이지에만 연결되어 있다.

- 실제 상태 전환 또는 공통 UI 처리에 숨김을 연결한다. PAUSED/INVENTORY/SHOP/AAR에서는 시간·예산을 보존하고 안내만 숨긴다.
- 타이틀/테스트 모드 전환에서는 상태·캐시·안내를 정리한다. GAME_OVER/VICTORY에서도 안내를 숨긴다.
- 플레이 복귀 시 현재 상태 안내가 정상 복원되는지 검증한다.
- `test_06_real_raw_dt_and_menus_test_mode_isolation`은 현재 director를 직접 호출하므로 실제 메인 루프 검증이 아니다. LiminalInfiniteLoop.update 또는 실제 전환 함수를 실행하는 테스트를 추가해 조기 반환 경로를 검증한다. GUI를 전부 띄울 필요는 없다.

## 4. 출현 실패 시 매 프레임 후보 전체 재검사

GateWaveManager는 성공한 경우에만 spawn_cooldown을 설정한다. 안전 위치가 없으면 6초 동안 매 프레임 모든 후보의 시야·충돌 검사를 반복한다.

- 성공 여부와 관계없이 실제 출현 시도 후 0.75초 재시도 간격을 적용한다. 목표 물량·총 출현 단계 시간·웨이브 예산은 기존 규칙을 유지한다.
- 출현 단계 시간이 이미 소진된 틱에서는 새 생성 시도를 하지 않도록 타임아웃 검사 순서도 정리한다.
- None을 반환하는 출현 함수의 호출 횟수/시각으로 간격을 검증한다. 부분 성공과 타임아웃 이후 호출 없음도 확인한다.

## 5. 보스 생성 프레임의 실행 순서

MonsterDirector.update_monsters가 웨이브를 먼저 갱신하고 38m 보스 생성 조건을 나중에 처리한다. 따라서 보스 출현 프레임에 일반 증원이 먼저 나올 수 있다.

- 해당 프레임에 보스 생성 조건을 먼저 처리한 뒤 웨이브를 갱신해, 생성된 보스가 즉시 일반 웨이브를 중단하도록 한다.
- stage>=3, boss_spawned=False, 관문 38m 진입, 출현 직전 웨이브라는 통합 사례를 검증한다. 보스가 미리 존재하는 테스트만으로 대체하지 않는다.
- 기존 보스 고유 소환 패턴(2페이즈 진입/주기적 소환)은 원 지시서의 '보스 패턴 유지'에 따라 보존한다. 보고서에는 '일반 웨이브 중지, 보스 고유 소환은 유지'라고 정확히 구분한다.
