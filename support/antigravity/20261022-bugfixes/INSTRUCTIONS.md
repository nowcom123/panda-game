# 작업 1: 판정·설정 버그 수정

## 역할과 목표

안티그래비티가 이 문서를 기준으로 현재 코드 확인, 구현, 회귀 테스트, 결과 보고까지 수행한다. 코덱스는 이 지시서 작성과 필요할 때의 결과 검토만 담당한다. 구현 전에 별도 장문의 계획 승인을 기다리지 말고 진행한다.

범위는 아래 6개 버그다. 증원 밸런스, 신규 콘텐츠, 성능 최적화, 전체 구조 개편은 다음 작업으로 남긴다. 줄 번호는 변경될 수 있으므로 함수 이름을 기준으로 찾는다. 분석 내용을 무조건 가정하지 말고 현재 실행 경로에서 확인한 뒤 고친다.

## 기존 작업 보존

- 먼저 적용되는 AGENTS.md와 git diff를 확인한다.
- 지시서 작성 시 이미 수정 중인 파일: combat_system.py, player_controller.py, ui_manager.py, weapon_recoil.py, tests/test_combat_hud_features.py, tests/test_weapon_recoil.py.
- 기존 반동·이동·HUD 수정은 보존한다. 파일 전체 교체, git reset/restore, 무관한 포맷 변경은 하지 않는다.
- 자동 커밋·푸시하지 않는다. rankings.json에 테스트 기록을 남기지 않는다. 임시 저장 경로 또는 mock을 사용한다.
- 새로운 패키지 설치 없이 기존 .venv를 사용한다.

## 1. 사용자 FOV 설정 유지

확인 위치: UIManager._adjust_setting / show_pause_menu, CombatSystem.update 마지막 FOV 계산, 게임 초기 camLens 설정.

문제: 설정 메뉴는 렌즈에 직접 FOV를 적용하지만 전투 루프는 기본 96도와 ADS 80도를 매 프레임 다시 적용한다.

요구사항:
- 사용자 기본 FOV를 단일 속성으로 보관한다. 메뉴 표시도 현재 효과 적용 후 렌즈 값이 아닌 이 설정값을 읽는다.
- 기본값 96도, 설정 범위 70~115도를 유지한다.
- ADS 목표는 기본 FOV * (80 / 96)로 계산해 기본 설정에서 기존 느낌을 유지한다. 불릿타임의 기존 +6.5도 효과도 유지한다.
- 조준·불릿타임 종료 후 설정한 기본 FOV로 복귀한다. 재시작과 스테이지 전환에도 유지한다.
- 디스크 설정 저장 기능을 새로 만드는 것은 범위 밖이다.

검증: 기본 FOV를 105로 변경하고 실제 전투 업데이트를 거친 뒤 유지되는지, ADS와 불릿타임을 적용/해제했을 때 정상 복귀하는지 테스트한다. 설정 함수만 호출하고 끝나는 테스트는 부족하다.

## 2. 보스 충격파 사망 처리

확인 위치: MonsterDirector.update_monsters의 보스 Ground Shockwave 분기, PlayerController.take_damage.

문제: 충격파는 take_damage(20)의 반환값을 사용하지 않아 다른 공격과 달리 즉시 게임오버를 호출하지 않는다.

요구사항:
- 치명타 시 trigger_game_over(killer=해당 보스, reason="killed")를 호출하고 디렉터 업데이트에서 즉시 종료 결과를 반환한다.
- 사망 후 같은 틱에 추가 보스 공격·슬로우·일반 피격 알림을 진행하지 않는다.
- 무적 시간과 비치명 피해의 기존 처리를 보존한다. 전 피해 시스템을 재설계하지 않는다.

검증: 치명/비치명/무적 상태에서 실제 충격파 분기를 실행한다. 치명 피해는 게임오버 1회, 후속 공격 없음, 비치명과 무적은 게임오버 없음.

## 3. 정예 외형과 판정 배율 일치

확인 위치: spawner.apply_elite_mutation, 정예 적용 가능한 5종 몬스터의 is_hit_by_ray 및 col_radius.

문제: 정예는 node.setScale(1.25)로 외형만 확대하는 반면 수동 사격 판정은 고정된 월드 좌표 오프셋과 반지름을 사용한다. 해골에서 확인되었으며 다른 종도 확인이 필요하다.

요구사항:
- 외형 배율과 수동 사격 판정의 중심 오프셋·반지름, 몸체 이동 충돌 반경이 일관되도록 고친다.
- 로컬→월드 변환 또는 명시적 배율 중 현재 구조에 맞는 최소 변경을 선택한다. 이미 월드 변환이 반영된 값은 중복 확대하지 않는다.
- 일반 몬스터의 판정과 헤드샷 구분, 회전된 몬스터의 판정을 보존한다.
- 모델 원점으로부터의 상대 오프셋을 확대한다. 월드 위치 자체를 곱하지 않는다.
- 노드 전체의 배율과 별도 몸통/세그먼트 구조를 구분해 처리한다. 무관한 보스 판정은 변경하지 않는다.

검증: 일반/정예 비교, 원점이 아닌 위치와 회전 상태, 머리/몸통/외곽 miss를 포함한다. 확대된 모델의 상단이나 측면에 맞는 사격이 판정되는지 확인한다. 수정한 몬스터 종마다 대표 사례를 검증한다.

## 4. 정지 상태에서 불릿타임 보존

확인 위치: LiminalInfiniteLoop.update, AudioManager.update_bullet_time 및 관련 시작/종료 함수.

문제: SHOP/INVENTORY/PAUSED/AAR 조기 반환 전에 bullet_time_timer를 감소시킨다.

요구사항:
- 게임 진행 중에만 게임플레이용 불릿타임 시간을 소비한다. 일시정지, 인벤토리, 상점, AAR에서는 남은 시간을 보존한다.
- 재개하면 남은 시간부터 지속하며 종료 효과는 한 번만 발생한다.
- 오디오의 효과 타이머도 확인해 시각 효과와 어긋나지 않게 한다. 메뉴 오디오 전체를 무조건 정지시키지 않는다.
- 정상 플레이에서 플레이어는 실시간, 몬스터·투사체는 기존 0.35배 속도라는 정책을 보존한다.

검증: 각 정지 상태로 여러 틱 진행해 잔여시간이 같음을 확인하고, PLAYING 복귀 후 감소·종료가 정상인지 확인한다.

## 5. 탈출 방어전 증원 타이머 초기화

확인 위치: EscapePortalManager.door_defense_spawn_timer, setup_escape_portal / update_door_defense, game.restart_game / advance_to_next_stage.

문제: 실제 사용값은 포털 매니저에 있지만 재시작과 다음 스테이지에서는 게임 객체의 동명 값을 초기화한다.

요구사항:
- 포털 매니저를 단일 소유자로 사용하고 중복 상태를 정리한다. 외부 참조 여부를 검색한 뒤 수정한다.
- 새 관문, 재시작, 다음 스테이지에서 0으로 초기화한다.
- 방어 영역 이탈로 개방이 취소될 때 증원 누적시간도 초기화한다. 재진입 후 온전한 2초가 지나야 방어전 증원이 발생한다.
- 몬스터 수 제한 및 다른 관문 증원 로직은 변경하지 않는다.

검증: 1.9초 누적 후 재시작/스테이지 전환/영역 이탈-재진입 각각에서 즉시 증원이 발생하지 않는지, 정상 연속 방어 2초에서는 1회 발생하는지 확인한다.

## 6. 개발 단축키와 일반 기록 분리

확인 위치: F5/F6/F7/F8 핸들러, F1 테스트 모드 진입, test_range.py, save_rank_record 호출부.

문제: F7은 일반 PLAYING에서도 경험치를 지급한다. 다른 개발 단축키도 같은 문제가 있는지 함께 확인한다.

요구사항:
- 전투 상태를 바꾸는 개발 단축키(F5~F8)는 기존 is_test_mode가 참인 경우에만 작동하게 한다. 등록 제한만으로 끝내지 말고 핸들러도 보호한다.
- F1 테스트 모드 진입과 테스트 모드 내 개발 기능은 유지한다. F11 화면 전환과 일반 입력에는 영향을 주지 않는다.
- 테스트 모드 플레이 결과가 일반 rankings.json에 기록되지 않도록 기록 진입점을 확인하고 필요한 가드를 추가한다.
- 테스트 모드에서 일반 게임을 새로 시작하면 정상적으로 일반 모드 및 기록 정책으로 돌아온다.

검증: 일반 플레이의 F5~F8이 경험치·퍽·몬스터 상태를 바꾸지 않는지, 테스트 모드에서는 기존 기능이 작동하는지 확인한다. 기록은 mock으로 차단 여부를 검증한다.

## 검증 방식과 완료 조건

1. 변경 전 기존 테스트를 실행해 기준 결과를 확보한다.
2. 각 버그에 대해 실제 분기를 실행하는 회귀 테스트를 추가한다. 문자열 검색이나 구현 코드 복제만으로 통과시키지 않는다. 가벼운 mock/NodePath 사용은 허용한다.
3. 실행 명령: `.\.venv\Scripts\python.exe -m unittest discover -s tests -q`
4. 새 테스트 포함 전체 테스트 통과, git diff --check 통과를 확인한다. 기존 테스트의 assertion 삭제나 skip 추가로 실패를 숨기지 않는다.
5. GUI 실행이 가능하면 FOV 변경→재개→조준, 정예 머리 사격, 불릿타임 중 일시정지, 방어 구역 이탈을 짧게 확인한다. GUI 검증을 못 했다면 명시한다.
6. 자체 diff 리뷰로 기존 수정의 보존과 작업 범위를 확인한다.
