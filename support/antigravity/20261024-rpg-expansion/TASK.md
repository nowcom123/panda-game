## A. 스테이지별 보스 성장과 패턴 추가

### A1. 성장

현재 `game.spawn_boss()`는 `CableOverlordBoss`를 생성만 하며, monster.py 기본 max_hp=3500,
speed=4.8, attack_damage=32다. boss_patterns.py는 sweep/spikes/leap/volley 피해를 각각 처리한다.
보스는 일반적으로 스테이지 3부터 등장하므로 **3층을 기존 난도 기준**으로 한다.

신규 boss_scaling.py 같은 순수 모듈에서 `depth=max(0, stage-3)`에 대해 다음을 계산한다.
- 체력 배율: 1 + 0.30*depth.
- 부위 내구도 배율: 1 + 0.18*depth.
- 공격 피해 배율: 1 + min(0.60, 0.08*depth).
- 이동 배율: 1 + min(0.15, 0.02*depth).
이 값은 첫 밸런스 기준이다. 상수로 분리하여 쉽게 조정할 수 있게 한다.

1/3/6/10층 기본 체력은 3500/3500/6650/10850이 된다.
생성 시 한 번만 적용하며 같은 보스에 재적용해 누적 곱셈하지 않는다.
hp와 max_hp, 각 다리 leg_hp가 일치하게 초기화하고 HUD가 새 max_hp를 사용하게 한다.
기존 director의 stage_mult 이동 배율과 중복 적용하지 않는다. 일반 적 배율은 유지한다.

피해 배율은 직접 타격뿐 아니라 보스가 발사한 투사체·충격파에도 적용한다.
기존 마녀/일반 적 투사체는 영향받지 않게 공격 생성 시 출처별 damage_scale을 전달한다.
풀링된 투사체는 activate 시 배율을 초기화하여 보스 다음에 마녀가 쏘면 배율이 남지 않게 한다.
보스 예고 시간은 최소 0.8초, 약점 노출/회복 기회는 유지한다. 무한 공격속도 증가는 금지한다.
HUD에 스테이지에 해당하는 보스 레벨과 부위 파괴 상태를 간결하게 표시한다.

### A2. 신규 기믹 2종

기존 sweep/spikes/leap/volley와 phase2 연계는 보존한다. 두 개의 새 패턴만 완성한다.

**뼈 부채꼴 파동 (3층부터)**
- 플레이어 방향을 예고 시작 시 고정하고, 안전한 부채꼴 통로를 남긴 바닥 파동을 발사한다.
- 최소 1초 예고, 안전 지대가 시각적으로 분명해야 한다.
- 위험 표시와 실제 판정의 반경/각도/진행 방향이 일치해야 한다.
- 한 파동이 같은 플레이어를 프레임마다 연타하지 않는다.
- 벽 반대편으로 피해가 통과하지 않는다. 안전 통로가 벽으로 막힌 좁은 곳이면 다른 패턴 선택.

**뼈 심장 봉인 (5층부터)**
- 보스가 최대 2개의 파괴 가능한 작은 봉인체를 생성하고 보호 상태가 된다.
- 보호는 피해 60% 감소이며 무적은 아니다. 봉인 파괴 또는 8초 경과 시 종료.
- 봉인 모두 파괴 시 보스 경직과 두개골 약점 노출 2초를 보상으로 제공한다.
- 봉인 위치는 접근/사격 가능한 빈 공간만 허용. 유효 위치가 없으면 패턴을 실행하지 않는다.
- 봉인은 기존 사격 판정에 명확히 참여하며 HP 표시/피격 반응을 갖는다. 일반 드롭/경험치 없음.
- 보스 사망/다리 파괴 중단/다음 층/새 런/메뉴 복귀 시 봉인·보호 효과·표시를 모두 정리한다.
- 일정 쿨다운을 두고 같은 패턴 연속 사용을 제한한다. 보호와 다른 대형 패턴을 겹치지 않는다.

기존 부위 파괴 연계: 다리 누적 4개 파괴 시 leap 선택 금지, 진행 중 leap는 안전 착지 후 회복.
파괴 수는 leg_hp에서 계산하고 새 중복 카운터를 만들지 않는다.
보스 새 시각 효과는 생성 수 상한을 두고 매 프레임 메시 재생성/동적 광원 남발을 금지한다.

검증: 단계별 스케일/재적용, 보스·마녀 풀 재사용 피해, 예고와 판정 일치, 안전 지대,
봉인 파괴/시간 종료, 다리 파괴, 모든 정리 경로, 보스 기존 패턴과 HP HUD.

## B. 캐릭터 생성·선택과 저장 분리

### 사용자 흐름

타이틀 → 캐릭터 선택/생성 → 해당 캐릭터로 탐험 시작.
처음에는 이름만 지정한다. 이름 2~12자(한글 허용, 양끝 공백 제거), 빈 이름/제어문자 거절.
최대 3명. 직업·외모 편집·캐릭터 삭제·계정 공유 창고는 이번 범위가 아니다.
캐릭터 카드에는 이름, 보유 장비 수, 주/보조 장비를 표시한다.
현재 레벨/퍽은 기존처럼 탐험 단위로 초기화되므로 UI에서 `탐험 레벨`로 구분한다.
영구 캐릭터 경험치/스탯 성장 시스템을 이번에 임의로 추가하지 않는다.

### 저장 설계와 기존 데이터 이관

- 신규 rpg/characters.py 등에 목록/선택/생성 관리.
- 캐릭터마다 기존 PlayerProfile 파일을 독립 저장한다. 아이템·장착·통화·해금이 서로 섞이면 안 된다.
- 캐릭터 ID는 UUID, 이름을 경로에 쓰지 않는다. 같은 이름은 허용하되 슬롯/선택 표시는 구분한다.
- 저장 루트 아래 `characters/<uuid>/profile.json`, 목록은 `characters.json`.
  목록에는 version=1, active_character_id, 각 id/name만 저장한다. 파일 경로는 ID로 계산한다.
- 목록도 검증·원자적 교체·백업·미지원 버전 차단을 적용한다.
- 기존 단일 profile.json이 있으면 **원본과 .bak를 지우지 않고** '기존 탐험가' 캐릭터로 이관한다.
  먼저 기존 SaveStore로 검증/복구 → 새 경로 저장 → 새 파일 재로드 검증 → 마지막으로 목록 커밋.
- 이관 도중 실패하거나 다시 실행돼도 장비가 중복되거나 두 캐릭터로 복제되지 않게 한다.
  예: 프로필 ID 기반의 결정적 UUID를 이관 목적지로 사용하고, 목록 완료 기록을 기준으로 재개한다.
- 미지원 버전/손상/읽기 실패를 빈 캐릭터로 덮지 않는다. 실패 이유를 보여주고 원본을 보존한다.
- 신규 캐릭터 기본품은 기존 starter_loadout_v1 정책대로 일반 게임 첫 시작 때 한 번만 지급한다.
- 캐릭터 전환은 타이틀에서만 가능. 탐험 중에는 금지한다.
  미확보 가방은 캐릭터 간 이전하지 않고, 포기 정책에 맞게 정리한다.
- 탈출 저장 실패 상태에는 캐릭터 전환/새 캐릭터 생성으로 우회할 수 없게 한다.
- 전투 세션, 장비 UI, 월드 드롭 catalog, HUD, 테스트 모드 복원 참조가 선택 캐릭터를 가리켜야 한다.
  새 캐릭터로 전환 시 item_states/예비탄/캐시도 정상 새 런 경로로 초기화한다.
- 기존 save_path/save_store 주입 검증 스크립트는 유지한다. 명시적 주입은 단일 캐릭터 검사 모드로
  취급해 자동 선택할 수 있지만, 기본 실제 사용자 경로의 캐릭터 화면을 우회하면 안 된다.

검증: 캐릭터 2명 간 장비/통화/잠금 격리, 재실행 선택 복원, 신규 지급 1회,
이관 성공/실패/중단 재개, 이전 원본 바이트 보존, 미지원 버전 차단, 경로 조작 불가,
탐험·탈출 저장 실패 중 전환 금지. 모두 TemporaryDirectory에서 실행한다.

## C. 인벤토리 UI 재정비

현재 장비/탐험 패널은 글자가 작고 빈 공간이 많으며 헤더/퀵슬롯 설명에 옛 입력 안내가 남아 있다.
기능을 추가로 늘리기보다 아래 정보 구조로 실제 UI를 재배치한다.

- 상단: 캐릭터 이름, `소모품 | 영구 장비 | 이번 탐험` 탭, 닫기.
- 영구 장비 탭: 왼쪽 주/보조 슬롯, 가운데 스크롤 보관함, 오른쪽 선택 장비와 슬롯 비교.
- 이번 탐험 탭: 용량 n/24와 소실 규칙, 아이템 목록, 상세 옵션.
  영구 장비와 색상/제목을 구분하고 `탈출 후 장착 가능`을 유지한다.
- 항목마다 이름/등급/레벨/장착/잠금 표식을 명확히 표시한다. 긴 이름 줄바꿈/잘림 처리.
- 버튼은 상태에 따라 활성화한다. 재료 장착/같은 UID 중복/마지막 무기 해제는 비활성화+이유.
- 비교 수치는 기존 resolve_weapon_config를 재사용한다. 공격력 증가/장전 시간 감소는 녹색,
  반대는 붉은색, 같으면 중립. 부여 옵션과 비교값을 섞어 쓰지 않는다.
- 등급/종류/이름 정렬을 제공하되 아이템 개체나 옵션을 수정하지 않는다.
- 선택 항목과 스크롤 위치를 장착/잠금 후 유지한다. 빈 목록/많은 아이템/한 슬롯 비움도 정상 표시.
- 소모품은 기존 사용 동작을 유지한다. 1/2=주/보조, 3/4=탄약팩/수류탄,
  Tab/I=가방이라는 현재 입력 규칙으로 헤더/푸터/HUD 안내를 일치시킨다.
- 주 화면 대비 충분히 불투명한 패널, 읽기 쉬운 한글 크기, 명확한 버튼 영역.
  신규 이미지 생성이나 별도 폰트/라이브러리 설치 없이 기존 에셋/DirectGUI를 활용한다.
- 1600×900 및 1280×720에서 직접 렌더 확인. 최소 40개 영구 장비/24개 미확보를 넣어
  겹침·텍스트 잘림·선택·스크롤·상호 배타적 탭 숨김을 검사한다.

## 수정 범위/반환

필요한 boss_scaling/캐릭터/UI 모듈은 새로 분리하고 game.py/ui_manager.py는 연결 중심으로 수정한다.
monster.py/boss_patterns.py/projectiles.py/monster_director.py/combat_system.py 변경은 위 기능에 한정한다.
기존 데이터 보호와 3단계 드롭/탈출 흐름을 깨뜨리지 않는다.
rankings.json·실제 사용자 저장·삭제된 원본 에셋을 건드리지 않는다. git reset/clean/commit 금지.
코드 작성 시 CRCRLF 줄바꿈을 만들지 않는다.

각 A/B/C 후 관련 검사를 실행하고 마지막에 전체 unittest, 임시 저장소 실제 게임 통합 검사,
캐릭터 화면과 두 해상도의 인벤토리 캡처를 남긴다. 순위 저장은 mock 처리한다.
RESULT.md에는 실제 구현 범위/변경 파일/실행 결과/미완료를 정확하게 기록한다.
사용자가 Codex에 '안티 작업 끝'이라고 전달하면 리뷰한다.
