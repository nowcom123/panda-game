## 1. 완료된 핵심 계약

### 강화

`rpg/workshop.py`의 RECIPES가 유일한 비용/배율 정의다.

| recipe_id | 이름 | 비용 | 기존 옵션 배율 변화 | 상한 |
|---|---|---|---|---|
| reinforce | 총열 보강 | 고철 8 | damage_mult +0.02 | 1.30 |
| weakpoint | 약점 각인 | 뼈 파편 6 | weakpoint_mult +0.05 | 1.50 |

카탈로그의 실제 재료명은 뼈 파편(bone_fragment)이다. 새 뼈가루 ID로 갈아끼우지 않는다.
옵션이 없으면 기본 배율 1.0에서 시작한다. 기존 무작위 옵션을 포함한 **최종 옵션 배율 상한**이다.
희귀도/아이템 레벨/UID/다른 옵션을 바꾸지 않는다. 확률 실패·강화 파괴·강화 단계 별도 필드 없음.
기본 공격력 +2%p, 약점 피해 보너스 +5%p 의미이며 현재 공격력에 매번 1.02/1.05 곱하는 것이 아니다.
예: damage_mult 1.10→1.12. 실제 공격력은 resolve_weapon_config 결과로 표시한다.

호출:
```python
from rpg.workshop import RECIPES, material_count
# 미리보기 (재료 부족/상한/잠금/잘못된 대상이면 ValidationError)
quote = game.rpg_session.quote_upgrade(item_uid, recipe_id)
# UpgradeQuote: profile_id, item_uid, recipe_id, material_id, cost, available, before, after
ok, message = game.upgrade_weapon(quote)
```

- UI의 실행은 반드시 `game.upgrade_weapon(quote)`를 통해 호출한다.
  INVENTORY + 일반 모드 + 정상 활성 세션에서만 실행 가능. 저장 실패 탈출 대기/사격장 차단.
- 잠금 해제된 영구 재료만 소비. 여러 UID의 재료 스택을 합산하고 빈 스택은 제거한다.
- 잠긴 대상 무기 거절. 장착 무기는 강화 가능. 미확보 가방/월드 드롭 사용 불가.
- 미리보기 이후 변경되었거나 같은 quote가 재사용되면 실패한다. 성공 후 새 미리보기를 만든다.
- candidate 사본을 한 번 저장한 뒤 메모리에 반영하고 캐시를 갱신한다. UI에서 별도 차감 금지.
- 강화 전후 공격력/장전/약점 비교는 동일 resolve_weapon_config를 쓴다.
  샷건 피해는 펠릿당 값임을 명시하고 펠릿 수를 함께 보여준다.
- 강화 후 `reset_state` 호출 금지(탄약 보충 버그 유발). 기존 세션 캐시가 갱신되어 전투에 반영된다.

### 캐릭터 삭제

핵심:
`CharacterManager.delete_character(char_id, confirmation_name=exact_name)`
게임 진입점:
`game.delete_character(char_id, confirmation_name) -> bool`

- 타이틀(INTRO)에서만 허용. 탐험/사격장/탈출 저장 실패 상태 차단.
- 정확한 이름 입력 요구. 같은 이름 캐릭터라도 ID로 대상을 지정한다.
- 목록 저장 실패 시 메모리/선택 복원. 실패 이유는 `game.character_error`.
- 현재 캐릭터 삭제 시 active_character_id=None, 세션/캐시 참조 해제.
  다른 캐릭터를 자동 선택하지 않는다. 남은 캐릭터 선택 또는 신규 생성 필요.
- 마지막 캐릭터 삭제 허용. 빈 목록 파일을 남겨 이전 단일 프로필이 자동 이관되지 않게 한다.
- **삭제 의미:** 플레이 목록에서 제거하고 슬롯을 확보한다. 기존 UUID 폴더의 저장 파일은
  실수 복구용으로 보존한다. UI 확인창에 이 사실을 명시한다. 물리 파일 삭제/자동 복구 UI는 없다.
- 기존 backup 정책상 이전 목록 백업으로 수동 복구할 수 있다. 영구 보안 삭제라고 표시하지 않는다.
- 파일 이동/삭제·새로운 목록 스키마·SaveStore 변경은 이번 범위가 아니다.

검사 파일: tests/test_rpg_workshop.py, tests/test_rpg_character_delete.py.
실제 사용자 저장/순위 파일을 읽어 검증하지 말고 임시 경로를 사용한다.

## 2. Antigravity 구현: 강화 화면

인벤토리에 네 번째 `작업대` 탭 추가. 탭 폭/위치를 다시 계산하여 겹치지 않게 한다.
기존 소모품/영구 장비/이번 탐험과 함께 하나의 탭만 표시된다.
신규 UI는 `rpg/workshop_ui.py` 등으로 분리하고 ui_manager.py는 연결 중심으로 변경한다.

구성:
- 왼쪽 무기 목록: 영구 소유 무기만, 선택/스크롤 또는 페이지 유지, 장착/잠금 표식.
- 중앙 강화 종류 카드 2개: 작은 금속/뼈 기하학 아이콘, 이름, 설명, 비용, 상한.
- 오른쪽 명확한 결과 카드: 현재 수치 → 강화 후 수치, 실제 증가량, 소모 재료, 실행 버튼.
- 상단 재료 배지: 고철/뼈 파편의 전체 수량과 사용 가능 수량(잠금 제외)을 구분한다.
- 재료가 부족해도 조리법 설명/비용은 보여준다. 버튼만 비활성화하고 이유를 표시한다.
- 강화 전 확인 영역에 정확한 무기명/등급/주·보조 상태와 변경값을 표시한다.
  성공 시 1회 피드백, 수량/수치/기존 장비 UI 갱신. 실패 시 사유, 기존 표시 유지.
- 장비 탭에서 재료 선택 시 사용처와 `작업대에서 사용` 이동 버튼을 보여준다.
- 이번 탐험 재료에는 `탈출로 확보 후 작업대에서 사용`을 표시한다.
- 사격장은 작업대 읽기 전용. 우회 콜백도 game.upgrade_weapon guard로 차단한다.

## 3. Antigravity 구현: 캐릭터 삭제 UI

- 각 캐릭터 카드 하단에 선택과 구별되는 작은 붉은 `삭제` 버튼.
- 삭제 확인 모달에 슬롯 번호/이름/장비 수, 목록에서 삭제됨과 파일 보존 설명.
- 이름 입력, 취소, 삭제 확정 버튼. ESC는 확인창만 닫는다.
- 이름이 정확히 일치할 때만 확정 버튼 활성화. 클릭 대상 ID는 모달 시작 시 고정한다.
- 실행은 game.delete_character를 호출. 성공 후 목록/활성 이름/시작 버튼 갱신.
- 실패는 모달을 유지하고 game.character_error 표시. 선택/세션을 UI에서 직접 수정하지 않는다.
- 현재/비활성/마지막/동일 이름/이미 삭제된 대상 각각 검사한다.
- 삭제 후 보관된 옛 UUID의 세션을 `_saved_rpg_session`이나 장비 패널에서 되살리지 않는다.

## 4. Antigravity 구현: UI 구분 도형과 시인성

사용자 요청은 텍스트만 늘리지 말고 **배경 카드·구획·구분선·배지·선택 테두리**로 정보가 나뉘게 하는 것.
새 래스터 이미지/외부 라이브러리 없이 DirectFrame, LineSegs, 기존 기하학 사용.

- 메인 인벤토리: 배경 불투명도 높임, 헤더/탭/본문/하단 안내 영역 명확히 분리.
- 장비 3열: 각 열 어두운 카드 배경과 얇은 경계선, 제목 아래 구분선.
- 아이템 행: 넓은 클릭 영역, 은은한 줄무늬 배경, 선택 시 밝은 테두리/왼쪽 표시막대.
- 희귀도: 텍스트 색만 쓰지 말고 작은 색 배지+등급 이름. 장착/잠금 별도 배지.
- 주/보조: 번호 배지 1/2와 카드 테두리로 비교 기준 슬롯 표시.
- 버튼: 색 면과 외곽선으로 클릭 가능한 영역 명확화. disabled는 색+사유 텍스트.
- 작업대: 재료 아이콘/수량 배지, 강화 전→후 카드, 소모 영역 구분선.
- 탐험 가방: 영구 장비와 다른 강조색, n/24 용량바, 미확보 경고 구획.
- 캐릭터 선택: 현재 선택 카드 외곽선/표식, 이름/장비/조작 구획 구분.
- 폰트는 검토에서 확대한 크기를 축소하지 않는다. 긴 이름은 줄바꿈/말줄임표.
- 도형은 UI 생성 시 만들고 텍스트/색/표시만 갱신. 매 프레임 도형 재생성 금지.
- 기존 입력 안내 유지: 1/2 주·보조, 3 탄약팩, 4 수류탄, Tab/I 인벤토리.
- 게임 안에 코드 파일명/API/구현 상세를 표시하지 않는다.

## 5. 검증·반환

기존 변경/삭제된 에셋 보존. git reset/clean/commit 금지. CRCRLF 생성 금지.
가급적 핵심 workshop.py/CharacterManager 저장 로직을 수정하지 않는다. 필요 발견 시 RESULT에 이유 기록.

1. 전체 unittest 통과.
2. 임시 경로의 실제 게임으로 작업대에서 장착 무기 강화, 비용 차감, 탄약 보존,
   게임에서 증가한 피해 설정, 재실행 후 저장 확인.
3. 재료 부족/잠금/상한/중복 확인/저장 실패/사격장/탈출 저장 실패 상태 차단.
4. 실제 게임 객체로 삭제 UI→빈 슬롯→생성→시작, 삭제 실패 시 기존 세션 보존 확인.
5. 1600×900, 1280×720 장비/작업대/가방(24개)/캐릭터/삭제 모달 캡처.
   보관함 40개 이상, 강화 옵션 3개, 긴 한글 이름과 동일 이름 캐릭터 포함.
6. 기존 전리품/탈출/캐릭터 전환 검토 스크립트도 임시 저장으로 확인.
7. 완료 범위/검증 명령·결과/한계를 같은 폴더 RESULT.md에 기록.

완료 후 사용자가 Codex에 `안티 작업 끝`을 전달하면 통합 리뷰를 진행한다.
