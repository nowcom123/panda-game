# 프레임 비용 측정 — 2026-10-24

## 환경과 방법

- CPU: AMD Ryzen 7 7800X3D. 렌더러가 보고한 GPU: NVIDIA GeForce RTX 4080 SUPER.
- 현재 게임 코드와 `.venv` 사용. 단일 렌더 파이프라인, 청크 25개.
- 실제 OpenGL 오프스크린 렌더링과 게임 `update`를 실행했다. 단순 AI 시뮬레이션이 아니다.
- 각 조건은 별도 프로세스에서 120프레임 예열 후 600프레임 측정했다.
- 고정 난수 시드, 일반 적 5종 균등 구성, 고정 1/60초 시뮬레이션 dt, 회전 시야.
- 플레이어는 이동 입력 없이 충돌·피격 처리되며, 적 AI·애니메이션은 동작한다.
- 프레임 제한과 VSync 해제, 오디오 장치는 null. 자동 증원은 차단했다.
- 생존 시간을 확보하도록 HP/시간을 늘렸다. 게임 본편의 설정·밸런스는 수정하지 않았다.

| 1600×900 | 20 | 16.266 | 24.615 | 1.651 | 1.364 |
| 1600×900 | 80 | 35.788 | 68.525 | 4.313 | 3.925 |
| 800×450 | 0 | 6.130 | 7.905 | 0.226 | 0.006 |

| 1600×900 | 80, 모델만 숨김 | 25.363 | 29.498 | 6.007 | 5.516 |

적 80마리에서 청크 컬링은 평균 0.033ms였다. 이 장면의 주요 비용은 아니다.
모델만 숨겨도 AI·애니메이션은 유지하며, 전체 시간이 줄었다. 다만 별도 실행 사이
CPU 시간에도 편차가 있으므로 차이를 순수 모델 렌더링 비용으로 단정하지 않는다.

## 함수 프로파일

별도 300프레임 실행에 cProfile을 켰다. 프로파일러 비용이 있으므로 위 프레임 수치와
직접 비교하지 않는다.

- `GraphicsEngine.renderFrame`: 7.049초 / 전체 프로파일 10.165초, 약 69%.
  이는 CPU 컬링·드로우 제출 및 드라이버/GPU 대기를 포함하며 순수 GPU 시간이 아니다.
- 적 80마리의 `GeomNode` 합계: 6,256개. 실제 드로우콜 수와 동일한 지표는 아니다.
- `NodePath.setColorScale`: 235,162회, 자체 시간 0.374초.
- `NodePath.setP`: 183,617회, 자체 시간 0.173초.
- `get_nearby_colliders`: 62,517회, 누적 0.441초.
- `pursuit_target`: 14,157회, 누적 0.906초.

## 해석과 우선순위

해상도를 1/4 픽셀 수로 줄여도 빨라지지 않았고, 적 수에 따라 렌더 경로 비용이 크게
증가했다. 현재 증거는 GPU 픽셀 처리량보다 CPU/드라이버의 오브젝트 처리 비용을
먼저 조사해야 함을 가리킨다. GPU 부족으로 확정할 근거는 없다.

1. 적 모델의 같은 뼈에 붙어 함께 움직이는 정적 부품을 병합하고 재질 상태 수를 줄인다.
   애니메이션 관절 전체를 합치면 동작이 깨지므로 관절 경계는 유지해야 한다.
2. 변화가 없는 색상을 반복 설정하는 코드를 찾아 상태가 바뀔 때만 적용한다.
3. 먼 적의 뼈 애니메이션 갱신 빈도와 모델 세부 수준을 조절한다.
4. 이후 충돌 후보 조회·경로 탐색 중복 계산을 줄이고 동일 시나리오로 재측정한다.

## 한계

실제 창을 띄운 플레이 FPS나 순수 GPU 프레임 시간을 측정한 것은 아니다.
현재 장면은 청크 이동 스트리밍, 보스, 지속 사격, 장시간 시체 누적을 포함하지 않는다.
각 조건은 1회 실행했으며 20마리 조건에서 실행 간 CPU 편차도 관찰됐다.
측정 도중 `nvidia-smi` 표본은 P8/210MHz, GPU 사용률 약 8~25%였다.
오프스크린·전원 상태와 다른 프로그램의 영향을 배제하지 않았으므로 실제 플레이 성능의
확정 수치로 사용하면 안 된다. 프로파일 실행의 프로세스 CPU 평균은 34.375ms,
전체 평균은 35.020ms였지만 프로세스 CPU 시간은 모든 스레드 합계이며 GPU 타이머가 아니다.

## 재실행

```powershell
.venv/Scripts/python.exe support/graphics/benchmark_game.py --enemies 80
.venv/Scripts/python.exe support/graphics/benchmark_game.py --enemies 80 --width 800
.venv/Scripts/python.exe support/graphics/benchmark_game.py --enemies 80 --hide-enemies
.venv/Scripts/python.exe support/graphics/benchmark_game.py --enemies 80 --profile --frames 300
```

다른 벤치마크와 동시에 실행하지 않는다. 원시 JSON과 프로파일은
`support/graphics/performance_results/`에 저장된다.

## 최적화 적용 후

같은 1600×900, 적 80마리, 예열 120프레임 + 측정 600프레임 조건이다.

| 항목 | 이전 | 정적 부품 병합 | 색상 그룹화·거리별 애니메이션 적용 |
|---|---:|---:|---:|
| 적 GeomNode 수 | 6,256 | 2,272 | 1,808 |
| 평균 프레임 시간 | 35.788ms | 25.473ms | 23.089ms |
| P95 프레임 시간 | 68.525ms | 36.584ms | 31.537ms |
| 게임 갱신 평균 | 4.313ms | 4.430ms | 3.819ms |

평균 프레임 시간은 약 35.5%, P95는 약 54.0% 줄었다. 실제 창 플레이의 개선율을
보장하는 수치가 아니며 위 측정 한계는 그대로 적용된다.

- `monster_visuals.py`에서 참조되지 않는 정적 형상만 같은 부모 아래 병합한다.
  관절, 피격 판정용 형상, 광원과 그 조상 노드는 유지한다. 보스 부위 파괴도 유지한다.
- 파수견 혈관의 색상을 관절별 그룹에 한 번씩 적용한다. 값이 같으면 재설정하지 않는다.
  300프레임 별도 프로파일의 `setColorScale` 호출은 235,162회에서 96,687회로 줄었다.
- 일반 적의 순수 포즈 갱신은 26m 밖 최대 20Hz, 40m 밖 최대 10Hz로 제한한다.
  기존 AI 틱 스케줄은 바꾸지 않았으며 상태이상·스턴 타이머는 포즈 생략 전에 처리한다.
  근거리·보스·공격 등 중요 상태는 제한하지 않는다. 누적 dt를 적용해 애니메이션이
  느려지지 않도록 한다. 기존 AI 틱에 따라 실제 포즈 빈도는 상한보다 낮을 수 있다.
- 이 벤치마크는 가까운 적이 많아 먼 거리 LOD 개선량을 따로 입증하지 않는다.
  144Hz 입력에서 먼 포즈 갱신 횟수와 누적 시간 보존은 별도 자동 검사로 검증했다.
- 일반 적 5종의 병합 전후 384×384 렌더 비교에서 평균 RGB 오차(0~1)는
  최대 0.000260이었다. 경계 래스터화 차이가 있으며 형상과 색상을 유지했다.

검증: 자동 테스트 166개, 보스 30초 패턴·죽음·정리 통합 검사, 모델 렌더 비교 통과.
최적화 결과는 `1600_80_batched.json`, `1600_80_optimized.json`에 보관한다.
최종 재실행에는 `--label optimized`를 붙여 이전 측정값을 보존할 수 있다.
